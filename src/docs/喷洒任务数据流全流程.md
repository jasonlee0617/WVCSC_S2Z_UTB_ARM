# WVCSC 全流程任务的数据流说明

本文只说明我执行完整导航喷洒任务时的数据如何流动、何时触发广域喷洒与机械臂喷洒，以及失败后如何收束。它适用于实机 `real_system_mission.launch.py` 和仿真 `system_sim.launch.py` 的共同任务链。单臂 Qt 测试复用 `/arm/execute_spray` 之后的机械臂链路，但不经过导航路线和广域喷洒判定。

## 1. 我看到的完整主链

```text
RViz 2D Pose Estimate / 2D Goal + Qt 录点
        │
        ├─ LoadManualMission ──> MissionManager ──> /mission/start
        │                                      │
        │                                      ├─ Nav2 NavigateToPose
        │                                      ├─ 车辆运动确认 ──> SetRelay(通道 1，广域)
        │                                      └─ 到站、停稳、可选停靠质量门控
        │                                                        │
        │                                  INSPECT ──> ExecuteSpray Action
        │                                                        │
        │     全画面病态检测 ─> Target2D 目标账本 ─> ComputeSprayAim
        │                                                        │
        │                             AlignTarget ─> Spray Action ─> SetRelay(通道 2，喷嘴)
        │                                                        │
        └──────────────────────────────────复检剩余目标、整株等待、HOME、Action Result
```

我不会让视觉检测结果直接开启广域喷洒，也不会让广域喷洒发送机械臂 Action。两者使用不同的触发来源、继电器通道和结束条件。

## 2. 我如何从 Qt 建立并启动路线

我先在 RViz 中给出定位初始位姿，再在 Qt 中确认当前起点。Qt 的 RViz 2D Goal 记录为机械臂基座锚点；通行点、病株检查点和终点组成一个 `ManualMissionTarget[]`。我手动勾选“开启广域喷洒”时，保存的是该目标**进入段**的 `wide_spray_on_approach`，不是病株本身的属性。

Qt 调用 `/mission/load_manual` (`LoadManualMission`) 把起点、路线、回起点选项和所有目标交给 `MissionManager`。该服务只加载和校验任务；随后 Qt 调用 `/mission/start` 才真正启动状态机。`/mission/status` 是 Qt 的执行状态来源。`/mission/plan` (`MissionPlan`) 是仿真和数据采集使用的只读摘要，不能作为 Qt 路线的完整回灌格式。

我录入终点时，系统强制将它的 `wide_spray_on_approach` 置为 `false`，所以终点不会开启广域喷洒。

## 3. 我何时触发广域喷洒

我只有在下列条件同时成立时才请求打开广域喷洒：

1. 当前导航目标的 `wide_spray_on_approach=true`；
2. Nav2 已接受该目标，任务处于导航状态；
3. 里程计新鲜，车辆线速度达到 `wide_spray_motion_linear_threshold`，当前默认值为 `0.03 m/s`；
4. `/relay/set` (`SetRelay`) 对通道 1 的开启请求返回成功。

这个速度确认是为了避免车辆尚未开始移动时就喷洒。若从 Nav2 接受目标起，车辆在 `wide_spray_motion_timeout_sec`（当前 10 秒）内未达到阈值，我继续导航，但保持通道 1 关闭。

我在以下事件发生时请求关闭通道 1：导航到站、车辆停止确认、导航失败或超时、取消或终止任务、进入 HOME、任务结束，以及进入一个未开启广域喷洒的下一导航段。通行点和终点都可以是纯导航点；只有通行点可以在其进入段独立开启广域喷洒，终点始终关闭。

`/spray/wide_active` 是 `MissionManager` 发布的 Transient Local 状态。它仅在通道 1 的服务请求**成功返回**后更新；关闭请求失败时，我保留最后一次确认状态，而不是把潜在仍开启的输出伪装成关闭。

## 4. 我何时触发机械臂单臂喷洒

我只有在当前点满足 `point_type=INSPECT`、Nav2 已到达停车位、车辆通过停稳检测后，才发送 `/arm/execute_spray` (`ExecuteSpray`) Goal。如果启用了 `require_docking_quality`，我还要求停车位的位置和航向误差通过阈值。车辆仍在运动、停稳超时或可选停靠质量不合格时，我不会移动机械臂；该点按既定回退或跳过策略收束，后续路线仍可继续。

发送 Goal 时，我传递任务 ID、病株 ID、每个病态目标的喷洒时长、病株提示坐标、观测模式和工作距离。完整导航任务使用 `working_range_m=0`，由正常几何链计算；单臂测试才允许人为覆盖工作距离。Goal 被服务端拒绝时不会产生自定义 Action Result，任务管理器会按拒绝路径处理。

## 5. 我在 ExecuteSpray 内执行什么数据流

`SprayTask` 是唯一的动作编排者。Goal 被接受后，我按下面顺序运行：

1. 我先将机械臂移动到观察位。`joint_presets` 使用侧位预设，`ik` 使用目标几何；碰撞、限位和奇异性等硬安全约束始终保留。
2. 我切换视觉推理并获取全画面病态目标。感知节点发布 `/vision/target` 与调试图；每个 `Target2D` 进入目标账本，按配置排序并执行最高目标数限制。
3. 我调用 `/arm/compute_spray_aim` (`ComputeSprayAim`) 获得固定工作平面上的喷嘴瞄准像素。它只计算，不发布机械臂运动命令；`working_range_m` 必须为正数，不能接受 0。
4. 我向 `/arm/align_target` (`AlignTarget`) 发送目标像素、图像尺寸和工作距离，视觉伺服据此输出受限的闭环运动。正常对准后继续；允许的软件回退只影响当前目标，不绕过碰撞、限位、奇异性或伺服硬安全停止。
5. 我向 `/arm/spray` (`Spray`) 发送喷洒请求。`SprayActuator` 是通道 2 正常开启和计时的所有者：继电器开启成功并真正进入计时后才发布喷嘴活动状态，喷洒结束、取消、锁定或清理后关闭。
6. 我在每个喷嘴喷洒完成后回观察位复检。已处理目标从队列出队；其余病叶仍在队列时继续检测和喷洒。该树所有目标处理完后，我等待配置的整株喷后等待时间，再回 HOME，最后返回 `ExecuteSpray` Result。

`ExecuteSpray.success=true` 可以表示完整成功 (`OK`)、已检查但没有病叶 (`INSPECTED_NO_DISEASE`) 或部分成功 (`PARTIAL_SUCCESS`)；调用方必须同时查看 `error_code` 和 `message`，不能只凭布尔值推断所有病叶都已喷洒。

## 6. 我使用的 Service、Action 与 Topic

| 接口 | 调用/发布方 → 接收方 | 我何时使用 | 成功后数据流 | 失败影响 |
|---|---|---|---|---|
| `/mission/load_manual` `LoadManualMission` | Qt → MissionManager | 录点后加载路线 | 校验后保存任务并发布状态/摘要 | 不开始任务，Qt 显示原因 |
| `/mission/start` `Trigger` | Qt → MissionManager | 已加载路线且操作者点击开始 | 进入导航状态并向 Nav2 送 Goal | 保持未启动 |
| Nav2 `NavigateToPose` | MissionManager → Nav2 | 每个路线点或 HOME | 到站后进入停稳/下一点 | 关闭广域并回退/跳过当前点 |
| `/relay/set` `SetRelay` | MissionManager 或 SprayActuator → 继电器 | 通道 1 广域、通道 2 喷嘴 | 成功确认后更新对应软件状态 | 保留最后确认状态；必要继电器故障按配置失效保护 |
| `/spray/wide_active` | MissionManager → Qt | 通道 1 服务成功后 | Qt 更新广域指示灯 | 无新状态时保持上次确认 |
| `/arm/execute_spray` `ExecuteSpray` | MissionManager/单臂 Qt → SprayTask | 检查点停稳后/手动单目标启动 | 观测、检测、伺服、喷嘴、复检、HOME | Result 驱动继续、跳过或失败 |
| `/vision/target` `Target2D` | 感知 → SprayTask/伺服 | 有效病态目标出现时 | 写入目标账本并用于当前瞄准 | 无有效目标按无病叶或视觉回退处理 |
| `/arm/compute_spray_aim` `ComputeSprayAim` | SprayTask → 瞄准计算器 | 已确定工作平面 | 返回喷嘴目标像素与图像尺寸 | 当前目标不能进入正常伺服 |
| `/arm/align_target` `AlignTarget` | SprayTask → VisualServo | 已有目标像素与图像 | 对准或给出允许回退/硬停止结果 | 当前目标按结果回退或中止 |
| `/arm/spray` `Spray` | SprayTask → SprayActuator | 对准或允许回退后 | 通道 2 计时喷洒 | 当前目标记为未完成并继续收束 |
| `/spray/simulated_active` | SprayActuator → Qt | 通道 2 成功开启/关闭 | Qt 更新喷嘴指示灯 | 无新状态时保持上次确认 |
| `/mission/status` `MissionStatus` | MissionManager → Qt | 状态变化时 | 显示任务阶段、当前点和错误 | 仅观测，不改变任务 |

`SetRelay.duration=0` 表示持续开启，调用方必须显式再发送关闭请求。项目约定通道 1 为广域喷洒、通道 2 为机械臂喷嘴喷洒。任务终止时，`MissionManager` 可以直接请求关闭全部通道；这不替代 `SprayActuator` 对正常喷嘴喷洒计时的所有权。

## 7. 我如何把喷洒状态显示在 Qt

Qt 始终显示两枚状态灯：

| 状态来源 | `true` | `false` | 尚未收到消息 |
|---|---|---|---|
| `/spray/wide_active` | 蓝色 `#1e88e5`，广域喷洒开启 | 灰色，关闭 | 灰色，未收到状态 |
| `/spray/simulated_active` | 红色 `#e53935`，喷嘴喷洒开启 | 灰色，关闭 | 灰色，未收到状态 |

这两枚灯表示**软件命令确认状态**，不是独立的继电器触点、电流或液体流量物理反馈。Gazebo 原有 `/relay/sim/channel_*_active` 和喷洒可视化仍服务于仿真模型，但不再作为 Qt 的跨实机/仿真状态来源。

## 8. 我如何结束、取消与恢复路线

正常情况下，病株 Action Result 回到 `MissionManager`：完成、无病叶或部分成功后，我进入下一个路线点；可恢复的视觉失败按当前点回退或跳过；HOME 失败、碰撞、限位、奇异性和伺服硬安全停止等必要硬门控仍会进入安全处理。每次路线完成、失败、取消、终止或 HOME，我都请求关闭通道 1 和通道 2。

Qt 的“终止任务”走终止导航、取消喷洒和机械臂 HOME 的既有链路。它不会用视觉伺服、继电器或运动控制的旁路命令替代 `MissionManager`/`SprayTask`。

## 9. 我如何理解完整任务与单臂测试的边界

完整任务使用 Qt 记录的地图停车位和病株相对 `alicia_base_link` 信息，且保持 `working_range_m=0`。单臂 Qt 测试只提交一个 `ExecuteSpray` Goal，可选择 `ik` 或 `joint_presets` 并显式覆盖工作距离。单臂测试中 `tool0` 的瞄准约定只是测试链路约定，不能把它当成完整实机喷嘴标定链的替代。

我用 `./run_real_arm_spray_server.sh` 时，脚本只启动 `real_arm_spray_test.launch.py` 及其默认 Qt；只有我在界面点击“启动”才会提交单目标 Action。

## 10. 我验收一条路线时检查什么

1. 我确认 Qt 已收到 `/mission/status`，且起点与任务点已加载。
2. 我确认未勾选“开启广域喷洒”的进入段不会打开通道 1；勾选后也必须先看到车辆速度达到阈值。
3. 我确认到站时广域蓝灯关闭，车辆停稳后才发送机械臂 Goal。
4. 我确认病叶目标在喷洒后出队，剩余目标继续被复检；整株结束后才等待并回 HOME。
5. 我确认通道 2 只在实际计时喷洒期间显示红灯，终止、失败和 HOME 后两灯均回到确认关闭或明确保留最后确认状态。
