# WVCSC 视觉感知与病态模型接入指南

本文档只描述感知架构与模型接入；YOLO、CUDA 和 Python 环境安装见《工控机 YOLO 依赖安装与 GPU 检查指南》。

## 架构

```text
/camera/.../image_raw
        │ 整幅 BGR 图像
        ▼
PerceptionPipeline
        ├── DiseaseSegmenter (segment) -> 掩膜安全点
        └── DiseaseDetector (detect)  -> 检测框中心
        ▼
目标跟踪、模板回退、排序、目标数量限制
        ▼
/vision/diseased_target_detections
/vision/diseased_target_debug_image
/vision/target (Target2D)
        ▼
视觉伺服 -> 喷洒 -> HOME
```

树检测、树视觉话题和树 ROI 已移除。路线和机械臂接口不再传递 `tree_id`；
`tree_hint` 仅保留为 `ExecuteSpray` 的植物几何提示，用于观察位和工作距离计算，
不属于视觉检测器输入或输出。

## 模块边界与坐标契约

| 模块 | 职责 |
| --- | --- |
| `disease_segmenter.py` | 固定 `segment` 权重推理，返回全图病态框与掩膜安全点。 |
| `disease_detector.py` | 固定 `detect` 权重推理，只返回全图病态框。 |
| `disease_backend_factory.py` | 按 `disease_model_backend` 创建一个病态后端。 |
| `perception_pipeline.py` | ROS 接线、模式切换、全图推理、跟踪、排序、调试和发布。 |
| `target_tracking.py` | 纯图像坐标下的 ID 关联和模板回退。 |

后端输入和输出都属于完整相机图像坐标系；后端不得自行裁剪、添加 ROI 偏移或发布 ROS 消息。`Target2D` 接口不变：segment 的 `center_u/v` 是掩膜安全点，detect 的 `center_u/v` 是检测框中心。

`/vision/inference_mode` 只接受 `idle`、`disease`、`target`：`disease` 发布当前画面的病态目标集合，`target` 跟踪 `/vision/selected_target_id` 指定的单个目标。

## 默认配置与接入

实机完整任务入口默认使用 `vision_real_detect.yaml`：`best.pt`、`detect`、原生类别
`illness`。`vision_real.yaml` 仍提供 `yolov8s_seg_real.pt` 的 segment 对比入口，必须
显式传入配置。仿真入口默认使用 `vision_sim.yaml` 的 `yolov8s_seg_sim.pt` segment
后端。所有后端均保持固定 ROS 输出类别 `diseased_target`，但权重内的原始类别名必须显式配置：

```yaml
disease_model_backend: detect
disease_model_path: best.pt
target_class_id: 0
target_class_name: diseased_target       # ROS 输出契约，固定不要拿来匹配权重 names
model_target_class_name: illness         # 实机 detect 默认；segment 按对应 YAML 配置
strict_model_classes: true
```

接入新的分割模型时，我设置 `disease_model_backend: segment`、权重路径和权重内原始
类别名；接入检测模型时，我设置 `disease_model_backend: detect`。多类别 detect
权重应设置目标类别 ID、`model_target_class_name` 和 `strict_model_classes: false`；
模型任务仍必须与后端一致。`target_class_name` 始终保留 `diseased_target`，这样
后续视觉伺服和喷洒链不会因实验模型原始类别名不同而变化。

```yaml
# 多类别 detect 实验模型示例
disease_model_backend: detect
disease_model_path: "<绝对路径>/disease_detect.pt"
target_class_id: 2
target_class_name: diseased_target
model_target_class_name: disease_leaf
strict_model_classes: false
disease_confidence: 0.25
```

如需接入非 YOLO 病态算法，实现 `DiseaseTargetBackend.detect(image, confidence)`，返回 `DiseaseTarget` 列表。纯检测后端必须保留 `control_u/control_v=None`，由流水线使用框中心；能给出可靠控制点的分割后端可填写二者。

## 构建、验证与回退

```bash
cd ~/WVCSC_S2Z_UTB_ARM
source /opt/ros/humble/setup.bash
colcon build --packages-select wvcsc_interfaces wvcsc_rgb_vision wvcsc_arm_task wvcsc_bringup wvcsc_simulation --symlink-install
source install/setup.bash
./run_system_sim.sh
```

实机单臂验证：

```bash
cd ~/WVCSC_S2Z_UTB_ARM
ros2 launch wvcsc_bringup real_arm_spray_test.launch.py \
  yolo_python_executable:="$HOME/venvs/wvcsc_yolo_ros/bin/python" \
  vision_config_file:="<绝对路径>/disease_detect.yaml"
```

实机完整路线可向 `real_system_mission.launch.py` 传同名 `vision_config_file`；仿真
向 `system_sim.launch.py` 传同名参数。默认不传时分别加载实机 detect 和仿真 segment
配置。模型任务、类别契约和检测精度仍需在目标设备上独立验收。

验收时确认：segment 安全点与 detect 框中心语义正确、实机仅有两个最高置信度目标、仿真可保留多个目标、无目标时返回 `INSPECTED_NO_DISEASE` 并继续任务、相机无帧或模型故障才返回 `VISION_FAILED`。

全图推理的背景更大、目标相对更小，可能与旧 ROI 流程有不同的召回或误检表现。应在同一 C10 图像或 rosbag 上验证，而不是把启动成功当作精度无回归证明。
