# WVCSC 实机硬件通讯口与设备检查指南

本文只做设备发现、端口确认和 ROS 数据链路检查，不在自动化测试中启动真实机械臂、底盘或
继电器。执行完整任务前，我先停止同一设备的其他驱动，避免两个节点同时占用串口或相机。

所有工作区命令都先进入工作区：

```bash
cd ~/WVCSC_S2Z_UTB_ARM
source /opt/ros/humble/setup.bash
source install/setup.bash
```

## 1. 设备总览

```bash
lsusb
dmesg --ctime | tail -n 80
ls -l /dev/video* /dev/ttyACM* /dev/ttyUSB* \
  /dev/serial/by-id /dev/serial/by-path 2>/dev/null || true
```

设备编号不是永久身份。`/dev/ttyACM0`、`/dev/ttyUSB0` 和 `/dev/video2` 可能随重新插拔或
USB 插口变化而改变；我使用 `by-id` 识别设备身份，使用 `by-path` 识别物理插口。

## 2. 机械臂串口

当前实机默认机械臂设备是 `/dev/my_robot`。它是指向机械臂 USB 串口的 udev 别名，当前通常
指向 `/dev/ttyACM0`，但不能把 `ttyACM0` 编号当作设备身份。

```bash
cd ~/WVCSC_S2Z_UTB_ARM
ARM_DEVICE=/dev/my_robot
ls -l "$ARM_DEVICE"
readlink -f "$ARM_DEVICE"
udevadm info --query=all --name="$ARM_DEVICE" | \
  rg 'ID_VENDOR|ID_MODEL|ID_SERIAL|ID_PATH|DEVNAME'
fuser -v "$ARM_DEVICE" || true

ros2 launch wvcsc_bringup real_arm.launch.py --show-args
```

确认没有其他机械臂驱动占用串口后，才进行驱动连通性检查：

```bash
cd ~/WVCSC_S2Z_UTB_ARM
ros2 launch wvcsc_bringup real_arm.launch.py \
  serial_port:="$ARM_DEVICE" baudrate:=1000000 use_rviz:=false
```

另一个终端检查关节状态：

```bash
cd ~/WVCSC_S2Z_UTB_ARM
ros2 control list_controllers
ros2 topic info /joint_states --verbose
ros2 topic hz /joint_states
```

不要直接向机械臂串口写入自定义字节。复位、运动和喷洒必须由现有 ROS 节点或 Qt 入口执行。

### 机械臂 USB 插口更换后的处理

先重新查看真实端口和物理路径：

```bash
ls -l /dev/serial/by-id /dev/serial/by-path
udevadm info --query=all --name=/dev/ttyACM0
udevadm info --attribute-walk --name=/dev/ttyACM0 | \
  rg 'idVendor|idProduct|serial|ID_PATH'
```

临时验证可以直接覆盖 launch 参数：

```bash
cd ~/WVCSC_S2Z_UTB_ARM
./run_real_system_mission.sh \
  serial_port:=/dev/serial/by-id/<机械臂实际设备>
```

如果以后希望永久固定为 `/dev/my_robot`，应根据上面命令得到的真实属性创建 udev 规则，
不要复制未经确认的 VID、PID 或序列号：

```text
KERNEL=="ttyACM*", ATTRS{idVendor}=="<实际VID>", \
ATTRS{idProduct}=="<实际PID>", ATTRS{serial}=="<实际序列号>", \
MODE="0660", GROUP="dialout", SYMLINK+="my_robot"
```

修改规则后重新加载：

```bash
sudo udevadm control --reload-rules
sudo udevadm trigger
ls -l /dev/my_robot
```

## 3. C10 相机

当前实机默认视频设备是 `/dev/video2`，图像话题是 `/camera/color/image_raw`：

```bash
CAMERA_DEVICE=/dev/video2
test -e "$CAMERA_DEVICE" && echo "camera exists" || echo "camera missing"
v4l2-ctl --list-devices
v4l2-ctl --device="$CAMERA_DEVICE" --all
v4l2-ctl --device="$CAMERA_DEVICE" --list-formats-ext
udevadm info --query=all --name="$CAMERA_DEVICE" | \
  rg 'ID_VENDOR|ID_MODEL|ID_SERIAL|ID_PATH|DEVNAME'
fuser -v "$CAMERA_DEVICE" || true
```

独立启动相机并检查 ROS 输出：

```bash
cd ~/WVCSC_S2Z_UTB_ARM
ros2 launch wvcsc_c10_camera c10_camera.launch.py \
  video_device:="$CAMERA_DEVICE"
ros2 topic info /camera/color/image_raw --verbose
ros2 topic hz /camera/color/image_raw
ros2 topic echo /camera/color/camera_info --once
```

相机端口变化时只覆盖 `c10_device`，不改变视觉话题：

```bash
cd ~/WVCSC_S2Z_UTB_ARM
./run_real_system_mission.sh c10_device:=/dev/videoX
```

## 4. 继电器串口

继电器配置由 `controller_pkg` 持有。使用安装包路径获取当前实际配置，不写死用户目录：

```bash
cd ~/WVCSC_S2Z_UTB_ARM
RELAY_CONFIG="$(ros2 pkg prefix controller_pkg)/share/controller_pkg/config/fault.ini"
sed -n '/^\[serial\]/,/^\[/p' "$RELAY_CONFIG"
grep -E '^(PortName|BaudRate|Address|Timeout)[[:space:]]*=' "$RELAY_CONFIG"

RELAY_DEVICE=$(awk -F= \
  '/^[[:space:]]*PortName[[:space:]]*=/{gsub(/[[:space:]]/, "", $2); print $2; exit}' \
  "$RELAY_CONFIG")
echo "relay device: $RELAY_DEVICE"
ls -l "$RELAY_DEVICE"
readlink -f "$RELAY_DEVICE" || true
udevadm info --query=all --name="$RELAY_DEVICE" | \
  rg 'ID_VENDOR|ID_MODEL|ID_SERIAL|ID_PATH|DEVNAME' || true
fuser -v "$RELAY_DEVICE" || true
```

启动继电器服务并查看接口：

```bash
cd ~/WVCSC_S2Z_UTB_ARM
ros2 launch controller_pkg controller.launch.py \
  config_file:="$RELAY_CONFIG"
ros2 service list | rg '^/relay/set$'
ros2 service type /relay/set
ros2 interface show wvcsc_interfaces/srv/SetRelay
```

项目约定通道 1 为广域喷洒，通道 2 为机械臂喷嘴。确认泵和喷洒装置处于安全状态后，
只能使用显式 OFF 请求进行软件路径检查：

```bash
cd ~/WVCSC_S2Z_UTB_ARM
ros2 service call /relay/set wvcsc_interfaces/srv/SetRelay \
  "{channel: 1, enabled: false, duration: 0.0}"
ros2 service call /relay/set wvcsc_interfaces/srv/SetRelay \
  "{channel: 2, enabled: false, duration: 0.0}"
```

`success: true` 只表示软件命令被后端接受或处理，不代表独立继电器触点、泵压力或液体
流量已经测量确认。

## 5. Yesense IMU

当前实机默认 IMU 别名是 `/dev/yesense_IMU`，波特率为 `460800`，标准消息话题为 `/imu`：

```bash
cd ~/WVCSC_S2Z_UTB_ARM
IMU_DEVICE=/dev/yesense_IMU
ls -l "$IMU_DEVICE"
readlink -f "$IMU_DEVICE"
udevadm info --query=all --name="$IMU_DEVICE" | \
  rg 'ID_VENDOR|ID_MODEL|ID_SERIAL|ID_PATH|DEVNAME'
fuser -v "$IMU_DEVICE" || true

ros2 launch yesense_std_ros2 yesense_node.launch.py
```

另一个终端检查输出：

```bash
cd ~/WVCSC_S2Z_UTB_ARM
ros2 topic info /imu --verbose
ros2 topic echo /imu --once
ros2 topic hz /imu
ros2 topic echo /imu_data_extend --once
```

端口或波特率变化时，修改 `yesense_std_ros2/config/yesense_config.yaml` 中的
`serial_port` 和 `baud_rate`，重新构建并重新 source；不要只依靠临时 `chmod 777`。

## 6. CAN 盒和底盘链路

本项目使用厂商 VCI CAN 盒，`can_bridge` 源码使用设备类型 4、设备索引 0 和两个通道。
它不是 SocketCAN，因此没有 `/dev/can0` 不代表设备故障。

```bash
cd ~/WVCSC_S2Z_UTB_ARM
lsusb
ros2 launch can_bridge can_bridge.launch.py
ros2 node list | rg 'can_bridge_node'
ros2 node info /can_bridge_node
ros2 topic list -t | rg '/can_(rx|tx)_[12]'
ros2 topic info /can_tx_1 --verbose
ros2 topic info /can_tx_2 --verbose
ros2 topic echo /can_tx_1
```

`/can_tx_1`、`/can_tx_2` 是 CAN 总线进入 ROS 的话题，`/can_rx_1`、`/can_rx_2` 是 ROS
发往 CAN 盒的输入话题。没有总线帧时，`topic hz` 没有输出不能单独证明设备掉线，应该同时
查看 `can_bridge` 启动日志中的设备打开和通道初始化结果。

## 7. 底盘、LiDAR、EKF 和 TF

```bash
cd ~/WVCSC_S2Z_UTB_ARM
ros2 node list | rg 'lslidar|wtb_car|ekf_filter_node|pointcloud_to_laserscan|yesense'
ros2 topic info /point_cloud_raw --verbose
ros2 topic hz /point_cloud_raw
ros2 topic echo /car_odom --once
ros2 topic echo /ekf_odom --once
ros2 topic hz /ekf_odom
ros2 run tf2_ros tf2_echo odom base_footprint
```

如果 `/imu`、`/car_odom`、`/ekf_odom` 或 `/point_cloud_raw` 没有数据，应先修复对应硬件
链路，再启动 Nav2 和完整任务。
