# 我执行 WVCSC 喷洒任务的完整数据流与判定条件

我用本文记录当前源码中的真实任务流程。本文同时覆盖完整任务和单臂测试：

- 完整任务：`real_system_mission.launch.py` / `system_sim.launch.py`；
- 单臂测试：`real_arm_spray_test.launch.py`；
- 两条入口最终都使用 `/arm/execute_spray`，所以我只在一个 `SprayTask` 中维护机械臂喷洒判定。

我会把“导航触发广域喷洒”和“检查点触发机械臂喷洒”明确分开。视觉检测只负责提供病态目标，
我不会让它反过来打开广域继电器，也不会因为导航到点就直接让机械臂运动。

## 1. 我先区分三个距离

| 名称 | 我的理解 | 使用者 | 是否直接决定机械臂位姿 |
|---|---|---|---|
| `tree_hint` 平面 XY | 病株相对机械臂基座的方向和距离 | 观察位、IK、动态喷嘴工距 | IK 会；预设模式只使用 Y 正负选择左右侧 |
| `working_range_m` | 相机到病株垂直平面的喷嘴标定工距 | `/vision/compute_spray_aim`、`AlignTarget` | 不直接移动机械臂，只改变瞄准投影平面 |
| 观察位 camera reach | 相机相对基座的候选伸出量 | `ObservationOptimizer` | 会，并且必须通过 MoveIt、安全 IK 和限位检查 |

我不会把 `working_range_m` 当成机械臂伸出距离，也不会用它绕过碰撞、关节限位、奇异性、Motion
锁定或 MoveIt 规划。

## 2. 我看到的整体架构

```text
我在 Qt/RViz 记录任务                 我在单臂 Qt 或脚本提交 Goal
          │                                      │
          ▼                                      ▼
   mission_manager ───── 导航、广域继电器、停稳门控 ────┐
          │                                             │
          └──────────── /arm/execute_spray ─────────────┘
                                │
                                ▼
                         wvcsc_spray_task
                  ┌─────────────┼─────────────┐
                  ▼             ▼             ▼
          perception_pipeline visual_servo spray_actuator
          全画面病态检测       AlignTarget   喷嘴/继电器
                  │             │             │
                  └──── /vision/target ──────┘
                                │
                                ▼
                         MoveIt Servo/控制器
```

我让 `mission_manager` 只决定“什么时候允许提交机械臂任务”，让 `wvcsc_spray_task` 成为单株喷洒的
唯一编排者，让 VisualServo 只处理锁定目标的闭环对准，让 SprayActuator 成为喷嘴继电器的唯一执行者。

## 4. 我如何区分两种喷洒触发

### 4.1 我的触发判定表

| 喷洒类型 | 我的触发来源 | 我必须确认的条件 | 实际接口 | 我在何时关闭或结束 |
|---|---|---|---|---|
| 广域喷洒 | 当前导航段 | `wide_spray_on_approach=true`、Nav2 Goal 已接受、里程计有效且线速度 `>=0.03 m/s`、继电器服务可用 | `/relay/set` 通道 1 | 到达、停止、取消、失败、HOME、启动等待超时 |
| 机械臂单臂喷洒 | 当前检查点 | `point_type=INSPECT`、Nav2 到达、车辆停稳；启用停靠门控时还要通过位置/航向误差 | `/arm/execute_spray` Action | Action 完成、回退、取消、硬失败、HOME |

### 4.2 我触发广域喷洒的过程

我在 Qt 中手动勾选“开启广域喷洒”时，只给驶向当前导航目标的路段设置
`wide_spray_on_approach=true`；我把这个选项默认关闭。

我只有在以下条件同时满足时才打开广域喷洒通道 1：

1. 当前目标的 `wide_spray_on_approach` 为 `true`；
2. MissionManager 处于 `NAVIGATING`，并且 Nav2 Goal 已被接受；
3. `/odom` 没有过期，车辆线速度达到 `wide_spray_motion_linear_threshold`，当前默认值为 `0.03 m/s`；
4. `/relay/set` 服务可用并成功打开通道 1。

我等待车辆开始运动的最长时间由 `wide_spray_motion_timeout_sec` 控制，当前默认值为 10 秒。
超时后我保持通道 1 关闭并继续任务，不让继电器无限等待或误开。

我在导航到达时先关闭通道 1，再进入停稳检测。我在取消、暂停、异常、导航失败、任务结束和回 HOME
时我也关闭通道 1，并在任务收尾阶段再次请求所有继电器关闭。

我不会因为病态目标检测结果而触发广域喷洒；广域喷洒也不会移动机械臂、不会发送
`ExecuteSpray` Goal。我可以让通行点和终点独立开启广域喷洒，也可以让检查点关闭广域喷洒。

### 4.3 我触发机械臂喷洒的过程

我只有在以下条件满足后才向 `/arm/execute_spray` 发送 Goal：

1. 当前目标的 `point_type=INSPECT`，因此 `target.requires_arm=true`；
2. Nav2 已报告到达；
3. `/odom` 连续通过停稳检测，车辆已经稳定；
4. 如果参数 `require_docking_quality=true`，当前位置和航向误差也通过配置阈值；
5. 我确认车辆不再运动，才允许机械臂移动。

如果停稳或停靠质量失败，我不会让机械臂在移动底盘上动作；当前检查点进入重试、恢复或跳过策略，
我让后续路线仍可继续执行；Nav2 的“到达”本身不是我的机械臂喷洒许可。

## 5. 我记录和提交完整任务

我先在 RViz 发布 `2D Pose Estimate` 完成 AMCL 初始定位，然后在 Qt 中记录起点。之后我按以下方式
记录任务点：

1. 通行点和终点使用 RViz `2D Goal`；
2. 病株检查点先记录车辆停车位，再点击树中心；
3. 我为每个点选择 `INSPECT`、`TRANSIT` 或 `FINISH`；
4. 对检查点我记录停车位、病株侧位、树相对机械臂基座的 `tree_x_m/tree_y_m/tree_base_z_m`、喷洒时长；
5. 我根据需要人工勾选该点的“开启广域喷洒”；
6. 我在 Qt 中调用 `/mission/load_manual`，确认预览无误后调用 `/mission/start`。

我明确区分两个继电器：广域喷洒使用通道 1，机械臂喷嘴使用通道 2；Qt 中的两个状态显示不会互相代替。

我在 MissionManager 中使用的主状态流是：

```text
READY → NAVIGATING → VERIFYING_STOP
                    ├─ INSPECT → ARM_SPRAYING
                    ├─ TRANSIT/FINISH → DWELLING
                    └─ 任务结束 → MISSION_COMPLETED 或 RETURNING_HOME
```

## 6. 我发送的 ExecuteSpray Goal 和准入条件

车辆停稳和可选停靠质量通过后，我构造：

```text
ExecuteSpray.Goal
├── mission_id
├── tree_id
├── spray_duration
├── tree_hint             # 完整任务中使用 map 坐标系
├── observation_mode      # 空字符串表示使用节点配置
└── working_range_m       # 0.0 表示动态树/相机几何计算
```

我的 Goal 只有在以下条件同时满足时才会被 Action Server 接受：

- `mission_id`、`tree_id` 非空；
- `spray_duration` 为有限数，并位于配置的 `0.2–10.0 s` 范围；
- `tree_hint.header.frame_id` 非空，XYZ 均为有限数；
- `observation_mode` 为空、`ik` 或 `joint_presets`；
- `working_range_m` 为 `0.0`，或位于 `0.20–2.00 m`；
- SprayTask 不忙，且 MotionControl 没有锁定。

我不把 Goal 被接受误解为机械臂一定会运动；后续观察、感知、Servo、继电器和 HOME 仍各自有硬门控。

## 7. 我执行一株病株的完整机械臂流程

### 7.1 我先移动到观察位

我先用 TF 将 `tree_hint` 转换到 `alicia_base_link`。

在 `joint_presets` 模式下，我根据病株在基座 Y 轴的正负选择左右预设；`abs(Y)` 小于侧位歧义阈值时，
我拒绝动作。center、fan_left、fan_right 仍然通过 MoveIt 关节空间规划和执行。

在 `ik` 模式下，我用 `hypot(tree_x, tree_y)` 做 `0.8–1.5 m` 工作范围门控，再对观察候选执行碰撞感知
IK、雅可比条件数、关节限位余量和 MoveIt 规划。只有全部通过的候选我才执行。

当前 IK 观察候选只使用平面 XY；`tree_hint.z` 不参与候选生成，但我保留完整 PointStamped 接口，
我这样保留它，以保证 TF 和完整任务接口稳定。

### 7.2 我获取并冻结病态目标

1. 我发布 `/vision/inference_mode=disease`；
2. `perception_pipeline` 在整幅 C10 图像上运行 `segment` 或显式选择的 `detect` 后端；
3. 我接收框、置信度、类别和控制点，并发布检测数组和调试图；
4. 我等待多帧稳定检测，不用单帧误检直接喷洒；
5. 首个稳定非空集合形成当前病株的逻辑账本，后续观察位只允许关联已有目标，不无限新增目标。

我在实机默认最多保留置信度最高的两个目标；仿真配置中的 `max_targets_per_tree=0` 表示不限制。
目标处理完后，我回到观察位重新检测并关联剩余目标。

### 7.3 我计算喷嘴瞄准点并进入 Servo

当 `working_range_m>0` 时，我使用单臂测试 Goal 的手动工距；当 `working_range_m==0` 时，我根据相机光轴
与树根垂直平面的交点计算动态工距。

我调用 `/vision/compute_spray_aim`，VisualServo 使用 C10 内参、手眼标定和 camera→喷嘴 TF 计算瞄准像素。
我把同一个工距、像素和图像尺寸同时传给 MoveIt 重心阶段和 `AlignTarget`，避免两个阶段对准不同位置。

我先发布 `/vision/selected_target_id`，再切换到 `target` 模式。目标离瞄准点较远时，我先进行有限角度的
MoveIt 重心；每次重心都重新做碰撞 IK、条件数、关节余量和轨迹规划。重心后我重新确认同一逻辑目标，
然后我在目标残差、关节状态和 Servo 预检都通过后发送 `/vision/align_target`。

VisualServo 以 30 Hz 计算零平移、角速度 Twist；MoveIt Servo 的实际发布周期由 YAML 决定。我在误差持续
我只在误差处于容差内的稳定时间满足后，才认为对准成功。

### 7.4 我按照失败类型选择回退

我在实机只允许针对明确的普通视觉失败进行回退喷洒，不能把所有失败都当成成功：

| AlignTarget 结果 | 我当前位姿喷洒 | 我回观察位后喷洒 | 我的处理 |
|---|---:|---:|---|
| `OK` | 是 | 不需要 | 我记录目标已处理 |
| `TIMEOUT` | 允许 | 允许 | 我可换观察位重试 |
| `TARGET_STALE` | 允许 | 允许 | 我可换观察位重试 |
| `SERVO_ACTUATION_STALL` | 允许 | 不走安全位回退分支 | 我可换观察位重试 |
| `SERVO_DIRECTION_DIVERGENCE` | 否 | 允许，但要重新预检并确认目标 | 我可换观察位重试 |
| `SERVO_SINGULARITY` | 否 | 否 | 我只能换观察位恢复/重试 |
| `SERVO_SAFETY_STOP` | 否 | 否 | 我立即停止并保持 `LOCKED` |

碰撞、关节限位、奇异性、Motion 锁定、目标身份无法确认、标定无效和继电器失败是我的硬门控，
我不会为了比赛连续性删除这些门控。

### 7.5 我打开机械臂喷嘴并继续目标队列

只有正常对准或表中明确允许的回退路径才能进入 `/spray/execute`。我确认 SprayTask 不忙、MotionControl
未锁定、喷洒时长有效，并在继电器通道 2 成功打开后开始计时。正常、取消和异常退出时我都会请求通道 2
关闭，并把继电器自身 duration 作为自动关断兜底。

一片病叶喷完后，我不会直接 HOME：

1. 我把该逻辑目标标为 `TREATED` 并出队；
2. 我返回当前安全观察位；
3. 我重新检测并关联冻结账本中尚未处理的目标；
4. 我继续处理第二个或其他剩余目标；
5. 即使第一目标走了回退喷洒，我也执行同样的回观察位和继续队列流程。

实机最多两个目标时，我在第二个目标处理完成或标记为 `unresolved` 后才结束整株流程。最终我要求：

```text
detected == sprayed + unresolved
```

账本不一致时我返回错误，不把任务伪装成整株成功。

### 7.6 我在整株结束后等待并回 HOME

我只有在所有冻结目标已经 `sprayed` 或 `unresolved` 后才进入最终 HOME。至少喷洒一次时，我在观察位等待
我在 `post_spray_home_delay_sec=2.0` 后再回 HOME；这 2 秒是整株结束后的一次等待，不是每片病叶都等待 2 秒。

我在等待期间仍接受取消。HOME 失败时我返回 `HOME_FAILED`；取消时我返回 `CANCELED`。

## 8. 我如何理解 tree XY

### 8.1 我在完整任务中保留 XY

我在完整任务中不能删除树根平面 XY，因为我用它：

- 把 map 坐标变换到 `alicia_base_link` 并确定左右侧；
- 在 IK 模式计算病株方向、距离和观察候选；
- 在 `working_range_m=0` 时定义病株垂直平面并计算动态工距；
- 检查车辆停靠后病株是否仍在机械臂工作范围。

我认为人为设置工作距离只能表达期望工况，不能表达真实方向和停靠误差，所以不能替代完整任务中的 XY。

### 8.2 我在单臂 `joint_presets` 中隐藏距离

预设关节角只由左右侧选择，病株距离不会改变 center/fan 关节值。因此我在单臂 Qt 中不显示基座到病株
距离，而在内部生成一个固定的侧位 hint。我必须正确选择左右侧，并使用有效手动工距。

### 8.3 我在单臂 `ik` 中保留侧位和距离

IK 仍需要平面方向和距离，所以我让单臂测试约定：

```text
左侧：tree_hint = (0, +base_distance, 0)
右侧：tree_hint = (0, -base_distance, 0)
```

我在 Qt 中保留病株侧位、`0.8–1.5 m` 基座距离和手动 `working_range_m`，删除自由输入的 XYZ。Z 当前不参与
候选生成，内部填写 0；如果未来需要任意方位或高度，我会扩展明确接口，而不是恢复难以理解的 XYZ 输入。

## 9. 我如何启动单臂后端和自动 Goal

我只启动后端、不自动执行时运行：

```bash
cd ~/WVCSC_S2Z_UTB_ARM/src
./run_real_arm_spray_server.sh
```

此时我不会自动发送 Goal、移动机械臂、回 HOME 或打开继电器；其他 launch 参数仍可以透传。

我需要脚本自动执行一次完整单臂流程时，必须显式提供全部 Goal 参数：

```bash
./run_real_arm_spray_server.sh \
  auto_execute:=true \
  observation_mode:=joint_presets \
  auto_side:=left \
  auto_tree_distance_m:=1.00 \
  auto_working_range_m:=1.00 \
  auto_spray_duration_sec:=3.00 \
  auto_mission_id:=arm_test_001 \
  auto_tree_id:=arm_tree_001
```

我把 `tree_hint.header.frame_id` 固定为 `alicia_base_link`，左侧使用正 Y，右侧使用负 Y。脚本先等待
`/arm/execute_spray` Action Server，再用 `ros2 action send_goal` 发送一个 `ExecuteSpray` Goal，随后等待
完整 Action 结果。我不让脚本直接发布 Servo、继电器或运动控制消息，所有运动和安全判定仍由 SprayTask 完成。

脚本中的 `auto_working_range_m=0.0` 表示恢复动态几何计算；正值表示单臂测试的手动瞄准平面覆盖值。
我让完整任务由 MissionManager 明确发送 `working_range_m=0.0`，不会受到单臂脚本参数污染。

如果我需要图形界面，我可以单独启动：

```bash
ros2 run wvcsc_bringup arm_spray_test_qt.py
```

或者直接使用原始入口一次启动后端和 Qt：

```bash
ros2 launch wvcsc_bringup real_arm_spray_test.launch.py
```
