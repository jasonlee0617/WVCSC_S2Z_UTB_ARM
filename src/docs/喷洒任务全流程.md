# WVCSC 全流程任务的数据流说明

本文说明我在实机 `real_system_mission.launch.py` 或仿真
`system_sim.launch.py` 中执行一条路线时，导航、广域喷洒、机械臂喷嘴喷洒和
视觉控制数据如何流动。单臂 Qt 测试复用机械臂 Action 链，但不经过路线导航和
广域喷洒判定。

当前实机主入口默认使用 `vision_real_detect.yaml`（detect、`best.pt`）；
`vision_real.yaml` 是显式传入时使用的 segment 对比配置。仿真入口默认使用
`vision_sim.yaml`。两种模式都保持 `/vision/*` 话题和 `Target2D` 消费接口不变。

## 1. 我使用的两类 ID 和两类路线点

我把路线身份与视觉目标身份分开：

| 数据 | 作用域 | 谁生成 | 用途 |
|---|---|---|---|
| `mission_id` | 一次已加载任务或单臂测试会话 | Qt / 调用方 | 关联同一次任务的状态和 Action |
| `point_id` | 一条路线内 | Qt | 标识一个导航路线点；不进入机械臂 Action |
| `target_id` | 一次连续视觉跟踪周期 | 感知流水线 | UUIDv4，锁定当前病态目标；不表示永久的物理病叶身份 |

路线由有序的 `ManualMissionPoint[]` 组成。`point_type` 是路线分流的唯一依据：

| `point_type` | Qt 名称 | 到站并停稳后的动作 |
|---|---|---|
| `POINT_TRANSIT=1` | 通行点 | 可选停留，然后继续下一点；不发送机械臂 Goal |
| `POINT_INSPECT=0` | 病株检查点 | 发送一次 `ExecuteSpray`，完成后继续下一点 |

最后一个数组元素就是路线终点；我不再使用单独的 `FINISH` 点类型。每个点都先
发送一个 Nav2 Goal。`wide_spray_on_approach` 是“进入该点的导航段”属性，和
`point_type` 相互独立：通行点和检查点都可以手动勾选，默认关闭。

## 2. 我如何从 Qt 录入并启动路线

我先在 RViz 给出定位初始位姿，再在 Qt 确认当前起点。Qt 接收 RViz 2D Goal，
把车辆停车位、`point_type`、`point_id`、广域喷洒选项和检查点的植物基座相对偏移
写入路线 JSON。检查点的 `tree_x_m`、`tree_y_m`、`tree_base_z_m` 是机械臂几何输入，
不是旧的 `tree_id`；`MissionManager` 再结合停车位生成 `ExecuteSpray.tree_hint`。

Qt 调用 `/mission/load_manual`（`LoadManualMission`）只加载并校验路线；成功后
`MissionManager` 发布只读 `/mission/plan`（`MissionPlan`）和 `/mission/status`
（`MissionStatus`）。Qt 随后调用 `/mission/start` 才真正开始导航。`MissionPlan`
是监控、仿真和数据采集摘要，不能直接作为编辑路线的回灌格式。

```text
Qt / RViz 录点
   │ LoadManualMission(points, home_pose, return_home_after_mission)
   ▼
MissionManager ── /mission/status、/mission/plan ──► Qt / 仿真采集
   │ /mission/start
   ▼
按数组顺序处理每一个 ManualMissionPoint
```

`return_home_after_mission=true` 只表示所有路线点处理完成后，再向 Nav2 发送一个
HOME Goal；它不改变最后一个点的类型，也不让 HOME 成为普通路线点。

## 3. 我如何触发和关闭广域喷洒

我只有在下列条件同时成立时才请求开启通道 1：

1. 当前点的 `wide_spray_on_approach=true`；
2. 本点 Nav2 Goal 已被接受，任务处于导航状态；
3. 里程计新鲜，车辆线速度达到 `wide_spray_motion_linear_threshold`
   （当前默认 `0.03 m/s`）；
4. `/relay/set`（`SetRelay`）的通道 1 开启请求返回 `success=true`。

如果车辆在 `wide_spray_motion_timeout_sec`（当前默认 10 秒）内没有达到速度阈值，
我继续导航但保持广域关闭。视觉检测、`Target2D`、机械臂状态和喷嘴状态都不会
触发广域喷洒，也不会让广域喷洒发送 `ExecuteSpray`。

我在到站、车辆停止确认、导航失败或超时、取消、终止、HOME、路线结束以及进入
一个未勾选广域喷洒的下一段时，请求关闭通道 1。`/spray/wide_active` 是
`MissionManager` 发布的 Transient Local 软件确认状态：只有服务调用成功后才更新。
关闭失败时，我保留最后一次确认值，不能把可能仍开启的输出伪装成关闭。

```text
Nav2 Goal accepted ──► 等待车辆实际运动 ──► SetRelay(channel=1, enabled=true)
       │                         │                         │
       └──── 条件不满足/超时 ────┴──── 保持关闭             └──► /spray/wide_active=true

到站、停止、失败、取消、HOME、结束 ──► SetRelay(channel=1, enabled=false)
```

## 4. 我如何触发机械臂喷嘴喷洒

我只在以下条件成立后发送 `/arm/execute_spray`（`ExecuteSpray`）Goal：

1. 当前路线点 `point_type=INSPECT`（接口常量为 `POINT_INSPECT`）；
2. 该点 Nav2 已到达；
3. 车辆通过里程计停稳检测，当前不再运动；
4. 任务没有被终止，机械臂不处于硬安全锁定状态。

我不再使用导航停靠质量门控。停稳超时、导航失败或 Goal 被拒绝时，我按本点的
回退/跳过策略收束并继续后续路线，而不会因为视觉软件条件停止整条路线；碰撞、
关节限位、奇异性和伺服硬安全停止仍是不可绕过的硬门控。

病株检查点默认要求 `stop_stable_duration_sec=1.0` 秒停稳；通行点使用
`transit_stop_stable_duration_sec=0.1` 秒。将通行点值设置为 `0.0` 时，只跳过
MissionManager 的通行点软件停稳确认，仍先关闭已确认的广域通道、保留该点的
`dwell_time_sec`，也不会把独立的 `NavigateToPose` 变成连续穿点导航。

完整路线发送的 Goal 包含 `mission_id`、每个病态目标的 `spray_duration`、带
坐标系的 `tree_hint` 和 `working_range_m=0`；观测模式由 `SprayTask` 的后端配置
决定。`working_range_m=0` 仅在 `ExecuteSpray` 中表示由机械臂任务按几何自动计算；
单臂测试才可以显式覆盖观测模式和正工作距离。路线 `point_id` 不进入
`ExecuteSpray`、`AlignTarget`、`Spray` 或 `Target2D`。

## 5. 我在 ExecuteSpray 内执行的完整数据流

`SprayTask` 是机械臂链的唯一编排者。Goal 被接受后，我按如下顺序执行：

```text
ExecuteSpray
  │
  ├─► 观察位（IK 或 joint_presets）
  ├─► 发布推理模式 → 全画面病态后端推理
  │       │
  │       └─► DiseaseTargetBackend → 跟踪 → Target2D(UUID target_id)
  ├─► 病态目标账本 / 选择 target_id
  ├─► ComputeSprayAim → 喷嘴轴目标像素与图像尺寸
  ├─► AlignTarget(mission_id, target_id) → MoveIt Servo
  ├─► Spray(mission_id, duration) → SetRelay(channel=2)
  ├─► 回观察位、复检、处理剩余目标
  └─► 整株喷后等待 → HOME → ExecuteSpray Result
```

我在视觉控制中只用 `mission_id + target_id` 过滤 `Target2D`。`target_id` 是感知
跟踪的 UUID；同一观察周期内稳定，跨观察位是否是同一物理病态目标由 `SprayTask`
的几何账本判定。它不会携带路线点 ID，也不依赖树检测。

病态后端处理整幅相机图像：

- `segment` 后端输出框和掩膜，`Target2D.center_u/v` 为掩膜安全控制点；
- `detect` 后端只输出框，流水线把框中心写入 `Target2D.center_u/v`；
- 两种后端的 ROS 输出类别都固定为 `diseased_target`，模型内原始类别名由
  `model_target_class_name` 配置，不与 ROS 类别混用。

正常对准后我进入喷嘴喷洒；允许的软件视觉回退只作用于当前目标，不能绕过碰撞、
限位、奇异性或伺服硬安全停止。每次喷嘴喷洒结束后我回观察位复检，已处理目标
从队列出队，剩余目标继续处理。整株完成后我等待配置的整株喷后等待时间，再回
HOME 并返回 Action Result。

`ExecuteSpray.success=true` 可能对应 `OK`、`INSPECTED_NO_DISEASE` 或
`PARTIAL_SUCCESS`；我必须同时读取 `error_code` 和 `message`，不能只用布尔值
断言所有病态目标均已喷洒。

## 6. 我如何理解喷嘴继电器和 Qt 指示

`SprayActuator` 是通道 2 正常开启和软件计时的所有者。仅当通道 2 的开启请求
成功并进入计时后，它才发布 `/spray/simulated_active=true`；正常结束、取消、
锁定和异常清理后发布 `false`。`MissionManager` 在终止流程可以直接请求关闭两个
通道，作为全局安全清理。

Qt 始终显示两枚软件命令确认状态灯：

| 话题 | `true` | `false` | 未收到状态 |
|---|---|---|---|
| `/spray/wide_active` | 蓝色 `#1e88e5`，广域开启 | 灰色，关闭 | 灰色，未收到状态 |
| `/spray/simulated_active` | 红色 `#e53935`，喷嘴开启 | 灰色，关闭 | 灰色，未收到状态 |

它们表示软件命令路径的确认结果，不是继电器触点、电流、泵流量或液体流量的独立
物理反馈。`SetRelay.success=true` 同样只表示当前后端接受/完成命令；定时开启时，
服务响应也不等待未来的自动关闭完成。

## 7. 我使用的接口与失败影响

| 接口 | 调用方 → 接收方 | 触发条件 | 成功后的下一步 | 失败影响 |
|---|---|---|---|---|
| `/mission/load_manual` `LoadManualMission` | Qt → MissionManager | 操作员加载路线 | 保存并发布 READY/摘要 | 不启动任务，Qt 显示原因 |
| `/mission/start` `Trigger` | Qt → MissionManager | 已加载路线 | 向当前点发送 Nav2 Goal | 保持未启动 |
| Nav2 `NavigateToPose` | MissionManager → Nav2 | 每个路线点或 HOME | 到站后停稳检测 | 关闭广域并回退/跳过点 |
| `/relay/set` `SetRelay` | MissionManager / SprayActuator → 继电器 | 广域或喷嘴命令 | 更新软件确认状态 | 保留最后确认状态并按调用方策略处理 |
| `/arm/execute_spray` `ExecuteSpray` | MissionManager / 单臂 Qt → SprayTask | 检查点停稳后 / 手动启动 | 观察、检测、对准、喷嘴、复检、HOME | Result 驱动继续、跳过或安全处理 |
| `/vision/target` `Target2D` | 感知 → SprayTask / VisualServo | 有效锁定病态目标 | 目标账本和伺服使用 | 无有效目标进入无病态或视觉回退路径 |
| `/arm/compute_spray_aim` `ComputeSprayAim` | SprayTask → VisualServo | 已确定正工作距离 | 返回喷嘴目标像素 | 当前目标不能进入正常伺服 |
| `/arm/align_target` `AlignTarget` | SprayTask → VisualServo | 已选择 UUID 目标 | 对准或给出回退/硬停止结果 | 当前目标按结果收束 |
| `/arm/spray` `Spray` | SprayTask → SprayActuator | 正常对准或允许回退后 | 通道 2 软件计时 | 当前目标未完成，继续收束 |

## 8. 我如何结束一条任务

路线点完成、跳过或得到允许的部分成功后，我推进到下一个数组元素。最后一个元素
完成后，我根据 `return_home_after_mission` 决定是否导航到 HOME；随后发布
`MISSION_COMPLETED`。全局终止、导航失败、HOME、硬安全锁定或任务结束时，我请求
关闭通道 1 和通道 2。Qt 的“终止任务”通过 `MissionManager` 和 `SprayTask` 的既有
取消/HOME 链处理，不使用视觉伺服、继电器或运动控制的旁路命令。

## 9. 我验收一条路线时检查什么

1. 我确认 `/mission/status` 使用 `current_point_id`，且每个路线点可从
   `/mission/plan.points[].point_type` 判定为通行或检查点。
2. 我确认未勾选广域喷洒的段不会打开通道 1；勾选后仍必须先看到车辆速度达到阈值。
3. 我确认只有 `POINT_INSPECT` 在到站和停稳后发送 `ExecuteSpray`。
4. 我确认 `Target2D` 没有 `tree_id`，视觉伺服只匹配 `mission_id + target_id`。
5. 我确认 segment 默认输出未改变，detect 实验后端使用框中心且不改变 ROS 话题。
6. 我确认终止、失败和 HOME 后两通道均请求关闭，Qt 灯显示确认关闭或保留最后确认状态。
