# WVCSC 喷洒任务完整数据流与机械臂判定条件

本文以当前源码为准，说明两条入口：

- 完整任务：`real_system_mission.launch.py` / `system_sim.launch.py`
- 单臂测试：`real_arm_spray_test.launch.py`

两条入口最终都调用同一个 `/arm/execute_spray` Action，并复用同一套感知、运动规划、
视觉伺服、喷洒继电器和 HOME 流程。节点数量会随实机/仿真、RViz、Qt 及控制器配置变化，
因此不使用固定“节点数”描述系统。

## 1. 先区分三个容易混淆的距离

| 名称 | 含义 | 谁使用 | 是否会直接决定机械臂位姿 |
|---|---|---|---|
| `tree_hint` 的平面 XY | 病株相对机械臂基座的方向和距离 | 观察位选择、IK、动态喷嘴工距 | IK 模式会；预设模式只使用 Y 正负选择左右侧 |
| `working_range_m` | 相机到病株垂直平面的喷嘴标定工距 | `/vision/compute_spray_aim` 和 `AlignTarget` | 不会；只改变喷嘴轴线在图像中的标定投影点 |
| 观察位相机 reach | IK 候选中相机相对机械臂基座的伸出量 | `ObservationOptimizer` | 会，且必须通过 MoveIt、安全 IK 和限位检查 |

`working_range_m` 不是“机械臂伸出距离”，也不是“强制允许喷洒距离”。手动修改它不能
绕过碰撞、关节限位、奇异性、Motion 锁定或 MoveIt 规划。

## 2. 总体架构

```text
完整任务 Qt/RViz                         单臂测试 Qt
  │ /mission/load_manual                  │ ExecuteSpray Goal
  │ /mission/start                        │
  ▼                                       │
mission_manager ──────────────────────────┤
  │ Nav2 /navigate_to_pose                │
  │ 停稳和停靠质量通过后                   │
  └─────────────── ExecuteSpray ──────────┘
                         │
                         ▼
                    spray_task
        ┌────────────────┼──────────────────┐
        │                │                  │
        ▼                ▼                  ▼
perception_pipeline  visual_servo      spray_actuator
全画面病态检测       AlignTarget        Spray Action
目标 ID/控制点        30 Hz 闭环         /relay/set
        │                │
        └──── /vision/target
                         │
                         ▼
                    MoveIt Servo
                         │
                         ▼
                 Alicia-M ros2_control
```

关键设计是：`mission_manager` 只决定“何时允许向机械臂提交任务”；`spray_task` 是单株
喷洒的唯一编排者；`visual_servo` 只处理锁定目标的闭环对准；`spray_actuator` 是喷嘴继电器
唯一执行者。启动脚本和 Qt 都不复制这些判定。

## 3. 主要 ROS 接口

| 接口 | 类型 | 数据方向 | 作用 |
|---|---|---|---|
| `/mission/load_manual` | `LoadManualMission` Service | Qt → MissionManager | 提交手动记录的路线 |
| `/mission/start` | `Trigger` Service | Qt → MissionManager | 启动已加载任务 |
| `/mission/status` | `MissionStatus` Topic | MissionManager → Qt/其他节点 | 当前任务状态 |
| `/mission/plan` | `MissionPlan` Topic | MissionManager → Qt | 当前路线快照 |
| `/navigate_to_pose` | Nav2 Action | MissionManager → Nav2 | 导航到停车位或通行点 |
| `/arm/execute_spray` | `ExecuteSpray` Action | MissionManager/单臂 Qt → SprayTask | 执行一株病株的完整处理 |
| `/vision/inference_mode` | `String` Topic | SprayTask → Perception | `idle`、`disease`、`target` |
| `/vision/diseased_target_detections` | `Detection2DArray` | Perception → SprayTask | 全画面病态目标集合 |
| `/vision/selected_target_id` | `String` Topic | SprayTask → Perception | 锁定当前逻辑目标 |
| `/vision/target` | `Target2D` Topic | Perception → SprayTask/Servo | 锁定目标的实时控制点 |
| `/vision/compute_spray_aim` | `ComputeSprayAim` Service | SprayTask → VisualServo | 按工距求喷嘴瞄准像素 |
| `/vision/align_target` | `AlignTarget` Action | SprayTask → VisualServo | 对单个锁定目标闭环对准 |
| `/servo_node/delta_twist_cmds` | `TwistStamped` Topic | VisualServo → MoveIt Servo | 视觉伺服速度命令 |
| `/servo_node/status` | `Int8` Topic | MoveIt Servo → VisualServo | 奇异、碰撞等 Servo 状态 |
| `/spray/execute` | `Spray` Action | SprayTask → SprayActuator | 打开喷嘴并计时 |
| `/relay/set` | `SetRelay` Service | SprayActuator/MissionManager → Relay | 控制物理或仿真继电器 |
| `/motion_control/command` | `String` Topic | Qt/任务节点 → MotionControl | `stop`、`reset`、`resume` |
| `/motion_control/locked` | `Bool` Topic | MotionControl → Arm/Spray | 机械臂硬锁状态 |

当前感知已经没有树检测阶段，也没有 `tree`/`fruits` 推理模式。病态后端直接处理整幅相机
画面；`segment` 后端的 `Target2D.center_u/v` 是掩膜安全点，`detect` 后端则是检测框中心。

## 4. 完整导航任务的数据流

### 4.1 Qt 记录任务

1. 在 RViz 发布 `2D Pose Estimate` 完成 AMCL 初始定位。
2. Qt 记录起点。
3. 通行点/终点使用一个 `2D Goal`。
4. 病株检查点先记录车辆停车位，再记录树中心。
5. Qt 形成 `ManualMissionTarget[]`，包含：
   - 点类型：`INSPECT`、`TRANSIT`、`FINISH`
   - 停车位姿
   - 病株侧位和树相对机械臂基座的 `tree_x_m/tree_y_m/tree_base_z_m`
   - 病株喷洒时长
   - 是否在驶向该点的路段开启广域喷洒
   - 到点停留时间
6. Qt 调用 `/mission/load_manual`，用户点击开始后调用 `/mission/start`。

“开启广域喷洒”是一个人工勾选的、默认关闭的来路属性。它控制通往该点的行驶区段，不是
机械臂喷嘴喷洒。广域喷洒使用继电器通道 1；机械臂喷嘴使用通道 2，两者不能混用。

### 4.2 导航、广域喷洒和停车判定

`mission_manager` 的主要状态流是：

```text
READY
  → NAVIGATING
  → VERIFYING_STOP
  ├─ INSPECT → ARM_SPRAYING
  ├─ TRANSIT/FINISH → DWELLING
  └─ 任务结束 → MISSION_COMPLETED 或 RETURNING_HOME
```

- Nav2 接受目标且检测到车辆开始移动后，才允许打开该路段的广域喷洒。
- 到点、取消、暂停、异常或任务结束都会请求关闭广域喷洒。
- Nav2 报告到达并不等于允许机械臂动作。
- `/odom` 必须通过连续停稳判定。
- 如果启用停靠质量检查，位置和朝向还必须满足停靠误差；不满足时先重试导航。
- 检查点停稳失败时跳过该检查点并继续后续路线，不能让机械臂在移动底盘上动作。

### 4.3 完整任务发送机械臂目标

停稳和可选停靠质量通过后，MissionManager 构造：

```text
ExecuteSpray.Goal
├── mission_id
├── tree_id
├── spray_duration
├── tree_hint             # map 坐标系中的真实树根点
├── observation_mode = "" # 使用 SprayTask 配置
└── working_range_m = 0.0 # 明确要求动态几何计算
```

完整任务不会使用单臂 Qt 的手动 `working_range_m`。`0.0` 是“按实际树平面和当前相机姿态
动态计算”的哨兵值。

## 5. ExecuteSpray 的完整机械臂流程

### 5.1 Goal 准入

Action Goal 只有同时满足以下条件才会被接受：

- `mission_id` 和 `tree_id` 非空；
- `spray_duration` 有限且位于配置的最小/最大时长内；
- `tree_hint.header.frame_id` 非空，XYZ 均为有限数；
- `observation_mode` 为空、`ik` 或 `joint_presets`；
- `working_range_m` 为 `0.0`，或位于 `0.20–2.00 m`；
- SprayTask 当前不忙；
- MotionControl 当前未锁定。

不满足时 Action Goal 会直接 `REJECT`。接口中的 `INVALID_GOAL`、`BUSY`、`LOCKED` 结果码
不能替代 GoalResponse 准入判定。

### 5.2 到达观察位

`tree_hint` 先通过 TF 转换到 `alicia_base_link`。

`joint_presets` 模式：

- 只根据病株在基座 Y 轴的正负选择左侧或右侧预设；
- `abs(Y)` 小于侧位歧义阈值时拒绝动作；
- center、fan_left、fan_right 都通过 MoveIt 关节空间规划和执行；
- 预设关节角不随病株距离改变。

`ik` 模式：

- 使用 `hypot(tree_x, tree_y)` 做 `0.8–1.5 m` 工作范围门控；
- 使用方向和距离生成相机观察候选；
- 对每个候选执行碰撞感知 IK；
- 检查雅可比条件数、关节限位余量和 MoveIt 规划；
- 只执行通过全部运动门控的候选。

当前 IK 观察几何使用平面 XY，`tree_hint.z` 不参与候选生成；Action 仍保留完整
`PointStamped`，以保持 TF 和完整任务接口稳定。

### 5.3 全画面病态目标检测

到达观察位后：

1. SprayTask 发布 `/vision/inference_mode = disease`。
2. `perception_pipeline` 在整幅 C10 图像上运行配置的病态后端。
3. 后端输出框、置信度、类别和控制点。
4. 感知侧分配/维持目标 ID，并发布检测数组和调试图。
5. SprayTask 等待多帧稳定检测，单帧误检不会立即进入喷洒。

实机存在两个独立的“最多两个”限制：

- 感知配置 `max_diseased_targets=2`：保留最高置信度的两个输出；
- SprayTask 配置 `max_targets_per_tree=2`：冻结本株最多两个逻辑目标。

仿真中值为 `0` 表示不限制数量。第一次稳定且非空的检测集合会冻结为本株逻辑账本，后续
观察位只允许重新关联这些目标，不允许把新框无限加入本株任务。

目标队列优先处理离配置图像中心较近的目标；置信度用于去重和同距离排序，不按喷嘴瞄准点
距离重新排序。

### 5.4 计算喷嘴瞄准点

每个目标进入重心或 Servo 前，SprayTask 确定工距：

```text
working_range_m > 0
  → 使用单臂测试 Goal 的手动覆盖值

working_range_m == 0
  → 当前相机光轴与树根垂直平面求交
  → 得到动态工距
```

随后调用 `/vision/compute_spray_aim`。VisualServo 根据 C10 内参、手眼标定和
camera→喷嘴 TF 计算喷嘴轴线在该工距平面上的像素 `(desired_u, desired_v)`。

同一个工距、像素、图像宽高会同时传给 MoveIt 重心阶段和 `AlignTarget`，防止粗对准与
视觉伺服瞄准两个不同点。CameraInfo、TF、工距或投影点非法时不能进入 Servo。

### 5.5 锁定目标、MoveIt 重心和 Servo 交接

1. SprayTask 发布 `/vision/selected_target_id`。
2. 感知切换为 `target` 模式并持续发布该目标的 `Target2D`。
3. 如果控制点离喷嘴瞄准点较远，先执行有限角度的 MoveIt 重心。
4. 每次重心都重新做碰撞 IK、条件数、关节余量和轨迹规划。
5. 重心后必须重新确认同一逻辑目标，防止误切到相邻病叶。
6. 目标残差进入 Servo 入口范围、关节状态新鲜且运动预检通过后，才发送
   `/vision/align_target`。
7. VisualServo 以 30 Hz 计算零平移、角速度 Twist；MoveIt Servo 的真实发布周期由各自
   YAML 决定，不等同于 30 Hz。
8. 误差 `target_center - desired_aim` 在容差内持续稳定时间后，AlignTarget 才返回成功。
9. 每个目标结束时发送多条零 Twist 制动；MoveIt Servo 只在首次需要时启动，不对每颗病叶
   反复暂停/启动服务。

### 5.6 对准失败的回退矩阵

实机 `spray_on_alignment_failure=true` 时也不是“任何失败都喷”。当前策略如下：

| AlignTarget 结果 | 当前位置喷洒 | 回安全观察位后回退喷洒 | 其他处理 |
|---|---:|---:|---|
| `OK` | 正常喷洒 | 不需要 | 记录已处理 |
| `TIMEOUT` | 允许 | 允许 | 失败时可换观察位重试 |
| `TARGET_STALE` | 允许 | 允许 | 失败时可换观察位重试 |
| `SERVO_ACTUATION_STALL` | 允许 | 不走安全位回退分支 | 可换观察位重试 |
| `SERVO_DIRECTION_DIVERGENCE` | 禁止 | 允许，但需重新预检和确认目标 | 可换观察位重试 |
| `SERVO_SINGULARITY` | 禁止 | 禁止直接喷 | 只允许换观察位恢复/重试 |
| `SERVO_SAFETY_STOP` | 禁止 | 禁止 | 立即 stop，返回 `LOCKED` |

安全位回退不是无条件喷洒。它必须先回到已规划的观察位，取得新鲜关节状态，再通过条件数、
关节余量等预检，并重新确认同一目标。

碰撞、关节限位、奇异性、Motion 锁定、目标身份无法确认、喷嘴标定无效、继电器失败等硬门控
不能因为比赛连续性而删除。删除这些门控会把“不中断演示”变成不可控误喷或碰撞风险。

### 5.7 喷嘴执行

只有正常对准或上表允许的回退路径进入 `/spray/execute`：

- Spray Goal 的 `mission_id/tree_id/duration/mode` 必须有效；
- SprayActuator 不能忙，MotionControl 不能锁定；
- 实机和仿真都使用 service 模式；
- 实机调用继电器通道 2，仿真由 `sim_relay.py` 提供同名服务；
- 收到继电器 ON 成功响应后才开始计时；
- 正常、取消或异常退出都请求 OFF；
- 继电器自己的 duration 是自动关断兜底。

`/spray/simulated_active` 是 Action 活动指示，不应当被当作物理喷嘴流量反馈。

### 5.8 每个目标喷后继续剩余队列

一片病叶喷完后不会直接 HOME：

1. 将该逻辑目标标为 `TREATED` 并出队；
2. 返回当前安全观察位；
3. 重新检测并关联冻结账本中尚未处理的目标；
4. 继续处理第二个或其他剩余目标；
5. 回退喷洒也执行同样的“返回观察位并继续队列”流程。

实机最多两个目标时，处理完第二个或将其判为 unresolved 后才结束整株流程。

最终必须满足：

```text
detected == sprayed + unresolved
```

否则返回账本不一致错误，不能假装整株成功。

### 5.9 整株结束、等待和 HOME

- 只有整株账本处理和最终复检完成后，才进入最终 HOME。
- 如果本株至少喷洒一次，默认在当前观察位等待
  `post_spray_home_delay_sec=2.0`，然后回 HOME。
- 这 2 秒是“整株完成后”的一次等待，不是每片病叶喷完都等待 2 秒。
- 等待期间仍可取消。
- HOME 失败返回 `HOME_FAILED`；取消返回 `CANCELED`。

结果汇总：

| 条件 | ExecuteSpray 结果 |
|---|---|
| 喷洒成功且无 unresolved | `OK` |
| 同时有 sprayed 和 unresolved | `PARTIAL_SUCCESS` |
| 检测到病态目标但全部未喷 | `VISION_FAILED` |
| 未检测到病态目标 | `INSPECTED_NO_DISEASE` |

## 6. 机械臂什么时候真正允许执行

下面的层级不能混为一个“喷洒开关”：

| 层级 | 必须满足的条件 | 失败后的上层策略 |
|---|---|---|
| Mission 提交机械臂 | Nav2 到点、底盘停稳、可选停靠质量通过、当前点为 INSPECT | 跳过检查点或暂停恢复 |
| Action 接受 | Goal 字段合法、不忙、未锁定 | 直接拒绝 Goal |
| 观察运动 | TF、侧位/IK 范围、关节反馈、碰撞规划、条件数、限位余量通过 | 安全回 HOME，返回失败 |
| 感知准入 | 全画面病态目标、类别/置信度、多帧稳定、目标 ID 可关联 | 换观察位或无病态结束 |
| Servo 准入 | 标定瞄准点、重心规划、新鲜关节状态、目标重确认、入口残差通过 | 恢复、回退或标记 unresolved |
| 喷嘴准入 | 对准成功或明确允许的回退码、未锁定、Spray Action/继电器可用 | 关闭继电器并返回失败 |
| 整株完成 | 所有冻结目标都已 sprayed 或 unresolved，账本守恒 | 不允许提前 HOME 并报成功 |

因此，“检测到病叶”只是感知准入的一部分，不等于立即打开喷嘴；“Action 已接受”也不等于
MoveIt 一定会执行轨迹。

## 7. MissionManager 对机械臂结果的处理

- `OK`：该点完成，继续下一点。
- `INSPECTED_NO_DISEASE`：视为已检查完成，继续下一点。
- `PARTIAL_SUCCESS`：记录部分成功，继续下一点。
- `OBSERVE_FAILED`、`VISION_FAILED`、`SPRAY_FAILED` 等普通点级失败：跳过当前点，继续路线。
- `CANCELED`、`HOME_FAILED`、`LOCKED`、`INTERNAL_ERROR`：视为关键失败，任务进入 FAILED。

这一区分实现“普通视觉问题尽量不中断路线”，同时保留机械臂硬安全和无法回 HOME 的终止能力。

## 8. tree XY 现在是否仍有作用

结论需要按入口区分。

### 8.1 完整任务：必须保留

完整任务中的树根平面 XY 仍然有实际作用：

- 从 map 变换到 `alicia_base_link` 后确定病株在左侧还是右侧；
- IK 模式用它计算距离、方位和观察候选；
- `working_range_m=0` 时用它定义病株垂直平面并计算真实动态工距；
- 可用于检查车辆停靠后病株几何是否仍在机械臂工作范围。

“人为设定机械臂工作距离”只设置期望工况，不能提供病株真实方向和实际停靠误差，所以不能据此
删除完整任务的 XY。

### 8.2 单臂 `joint_preset`：界面可删除距离

预设关节角只由左/右侧选择，病株距离不会改变 center/fan 关节值。单臂 Qt 因此不再显示
基座到病株距离，而是在内部生成一个固定、非真实的侧位 hint；手动 `working_range_m` 提供
喷嘴瞄准平面。

这个简化只成立于：

- 病株已由人工摆放在预设动作验证过的物理区域；
- 操作者正确选择左右侧；
- 使用正值手动工距，避免依赖合成 hint 计算动态工距。

### 8.3 单臂 `ik`：保留侧位和基座距离

IK 模式仍需要平面方向和距离。为简化 UI，单臂测试约定病株位于机械臂正左或正右：

```text
左侧：tree_hint = (0, +base_distance, 0)
右侧：tree_hint = (0, -base_distance, 0)
```

因此 Qt 保留：

- 病株侧位；
- 基座到病株距离，范围 `0.8–1.5 m`；
- 手动 `working_range_m`；
- 喷洒时长。

Qt 删除自由输入的 X/Y/Z。Z 在当前 IK 候选生成中未使用，内部填写 0；如果未来需要任意方位
或按病株高度生成观察位，应重新扩展明确的方位/高度接口，而不是把三个难以理解的 XYZ 输入
直接放回界面。

## 9. 单臂 Qt 的字段和行为

| 字段 | `joint_preset` | `IK` |
|---|---:|---:|
| 病株侧位 | 必填 | 必填 |
| 基座到病株距离 | 不显示，使用内部侧位 hint | 必填，0.8–1.5 m |
| 工作距离 | 必填，0.20–2.00 m | 必填，0.20–2.00 m |
| 喷洒时长 | 必填 | 必填 |
| 自由 X/Y/Z | 删除 | 删除 |

按钮保持单目标模式：

- “启动”：发送一个 ExecuteSpray Goal；
- “复位”：停止当前运动、取消 Action，随后请求 HOME；
- “HOME 完成后解锁”：只有状态为 `HOME_LOCKED` 时发送 resume；
- “显示相机/YOLO画面”：默认勾选，可折叠图像面板。

单臂 Qt 的手动工距只写入该次 Goal。完整任务始终显式写入 `0.0`，两条模式互不污染。

## 10. 同事启动单臂喷洒后端

源码根目录提供：

```bash
cd ~/WVCSC_S2Z_UTB_ARM/src
./run_real_arm_spray_server.sh
```

该脚本只做三件事：

1. 加载 ROS 2 Humble；
2. 加载当前工作区 `install/setup.bash`；
3. 启动 `real_arm_spray_test.launch.py use_qt_gui:=false`。

它会启动现有的真实控制器、MoveIt、C10、感知、VisualServo、MotionControl、SprayTask 和
SprayActuator，但不会自动发 Goal、自动运动、自动 HOME 或自动打开继电器。所有 launch 参数
可继续透传，例如：

```bash
./run_real_arm_spray_server.sh \
  serial_port:=/dev/ttyACM1 \
  observation_mode:=ik
```

在第二个已加载工作区环境的终端启动界面：

```bash
ros2 run wvcsc_bringup arm_spray_test_qt.py
```

也可以直接使用原始入口，一次启动后端和 Qt：

```bash
ros2 launch wvcsc_bringup real_arm_spray_test.launch.py
```

脚本只是启动入口，不是新的判定服务器。唯一权威判定仍由 `/arm/execute_spray` 对应的
`wvcsc_spray_task` 完成，避免同一安全条件在两个节点中出现不一致。

## 11. 实机与仿真的关键差异

| 项目 | 实机 | 仿真 |
|---|---|---|
| 默认观察模式 | `joint_presets` | `ik` |
| 感知后端 | 默认 `segment`，最多两个输出 | 默认 `segment`，目标数量不限 |
| SprayTask 目标上限 | 2 | 0，表示不限 |
| VisualServo 控制循环 | 30 Hz | 30 Hz |
| MoveIt Servo 发布周期 | 0.05 s（20 Hz） | 0.10 s（10 Hz） |
| 对准失败喷洒 | 实机配置允许限定回退码 | 默认关闭 |
| 喷洒继电器 | 真实 `/relay/set` | `sim_relay.py` 提供同名服务 |
| 整株喷后 HOME 等待 | 2.0 s | 2.0 s |

修改参数时必须区分“代码 fallback”“仿真 YAML”“实机 YAML”，不能把一套数值当成两个环境
的共同真值。

## 12. 最小验收清单

### 静态和构建

```bash
cd ~/WVCSC_S2Z_UTB_ARM
source /opt/ros/humble/setup.bash
colcon build --packages-select \
  wvcsc_interfaces wvcsc_arm_task wvcsc_mission_manager wvcsc_bringup
source install/setup.bash
ros2 interface show wvcsc_interfaces/action/ExecuteSpray
bash -n src/run_real_arm_spray_server.sh
ros2 launch wvcsc_bringup real_arm_spray_test.launch.py --show-args
```

### 单臂功能

- `joint_preset` 左、右两侧各执行一次，确认 UI 不显示基座距离。
- IK 左、右两侧分别用 0.8 m 和 1.5 m 边界测试。
- 两种模式确认手动工距写入 Goal，且不调用动态树平面工距。
- 正常目标喷洒后返回观察位，继续第二目标，整株结束后等待 2 秒再 HOME。
- 按“复位”后继电器关闭、Action 取消、机械臂 HOME，随后可解锁。

### 完整任务回归

- MissionManager 发送的 `working_range_m` 必须始终为 `0.0`。
- 原 map-frame `tree_hint` XYZ 不变，并继续走动态工距。
- 广域喷洒通道 1 与机械臂喷嘴通道 2 状态独立。
- 普通视觉失败只跳过当前点；`LOCKED/HOME_FAILED` 等硬失败不能继续伪装成功。
- 实机测试必须保留物理急停，并先进行低速、无液体联调，再接入喷液。
